# 04 参考研究与赛事边界

核实日期：2026-11-03。竞品信息来自TapTap公开产品介绍及更新说明，赛事信息来自主办方原文；未亲自试玩两款竞品，不将页面宣称当成实机验证。本文不复制第三方源码、截图、音乐、剧情或完整文章。

## 1. 两款参考作分别提供什么

### 《网约车：接单人生》

[TapTap产品页](https://www.taptap.cn/app/995770)

公开介绍强调亲自驾驶、在城市街巷连续接单、轻松不催促和及时收益反馈。更新说明提到订单定价、长途订单、乘客评价、车辆与住宅购买，以及漂移、碰撞相关调整。

本项目借鉴的是：驾驶过程本身值得停留，订单完成迅速给出回报，资产成长把重复驾驶串起来。转译为船体惯性、海面氛围、宽容靠港和可见换船。

不能由这些资料确认该作单次订单20–30秒、精确结算公式、操作按钮细节、完整接送步骤或自动船队式经营。本站资料不作为这些数值的依据。

### 《网约车：从一辆破车干到一百辆》

[TapTap产品页](https://www.taptap.cn/app/948470)

官方介绍描述500元开局租旧车、派单后8秒决定接否、比较起终点与价格，并在路线速度、过路费、油耗及拥堵风险之间取舍；还介绍路途中事件、二手车车况/验车/议价，以及自己完成20单后开启车队、租车交司机运营。页面宣称51类事件与16位熟客各三集故事，这些是介绍数量，未经过独立实测。

本项目借鉴“看单判断 → 选路 → 完成订单 → 资产扩张 → 委托运营”的结构，不照搬其8秒决策压力、生活费用、百车规模或内容数量。首版只做少量可理解的货运和最多三船。现有资料不足以确认其完整实时手动驾驶操作、离线收益算法、司机分类或百车后期体验。

### 机制转译表

| 参考价值 | 航运转译 | 为何保留/改变 |
|---|---|---|
| 亲驾与日常氛围 | 海面手动驾驶、入港、货箱卸载 | 保留“我完成这单”的亲历感 |
| 起终点和报价选择 | 港口、货物、固定实收、到港行情 | 在短循环里保留一个小判断 |
| 路线风险/成本取舍 | 宽水道与近岸捷径、航时与完好奖励 | 让操控和经营互相影响 |
| 旧车到车队 | 旧船、小升级、第二艘船、助手单程 | 压缩成长规模，适配短篇 |
| 路上事件 | 优先使用供需状态反馈 | 减少文案和系统膨胀 |
| 本项目新增假设 | 运输改变库存与下一单有利航路 | 用于验证SHIFT是否进入决策 |

“20–30秒一单”“四港三货”“三艘船”“供需公式”和“玩家运输改变商路”全部是本项目设计目标，不是竞品已验证机制或主办方要求。不得宣传为两款参考作的复刻，也不宣称全球首创。

## 2. 本届官方规则对方案的约束

### 已核实事实

- 主题为SHIFT，解释宽松；不要求按Shift键、换挡或必须采用某类玩法。[赛事主页](https://itch.io/jam/game-off-2026)
- 当前提交截止为**2026年12月1日21:37 UTC，北京时间12月2日05:37**；投票截止为2027年1月1日同一UTC时间。提交前仍应复核官方页面。[赛事主页](https://itch.io/jam/game-off-2026)
- 评分列Overall、Gameplay、Graphics、Audio、Innovation、Theme Interpretation，由参赛者及队友互评。没有已核实的官方百分比权重，不把内部测试指标写成获奖公式。[主办方FAQ](https://itch.io/jam/game-off-2026/topic/7290154/frequently-asked-questions-faq)
- 正式参赛要提供GitHub公开游戏源码和itch.io可玩提交，上传研究策划或仅推代码不等于完成参赛。[GitHub官方公告](https://github.blog/open-source/gaming/game-off-2026-the-theme-is-shift/)
- 公开源码不等于必须采用某种开放源代码许可证。代码和资产可采用不同许可；资产需要有使用权并满足署名。不能再分发的资产可提供占位和说明。[主办方FAQ](https://itch.io/jam/game-off-2026/topic/7290154/frequently-asked-questions-faq)
- 允许AI辅助代码、美术或音乐等，但提交时须披露。允许模板与复用代码，绝大部分开发应发生在赛期，旧游戏只作少量修改不符合此要求。[主办方FAQ](https://itch.io/jam/game-off-2026/topic/7290154/frequently-asked-questions-faq)

### 对本方案的具体影响

1. 主题解释要展示实际运输如何改变后续选择，而不只在开场解释“商路转移”。这是一项设计要求，不是主办方预先认可本方案。
2. 浏览器优先、12–18分钟短篇、简短英文提示是减少试玩摩擦的制作建议，不是官方强制平台、时长或语言。
3. 不能因为已有私有航海项目就默认整份移入公开仓库。赛期开发占比、复用代码、资产和授权都须独立检查。
4. 若将来参赛，需保存源码哈希、构建对应关系、复用清单、许可证/资产来源和AI披露。公开可见与允许他人再使用是不同问题。
5. 不刷票、不承诺互换高分、不虚构测试或贡献者，不把排名当一般市场用户的商业验证。
