# 地中海航运游戏系统策划初稿

版本：v0.1 · 2026-11-03 · 当前推进方向。暂用工作名《地中海航运：转向商路》，英文工作名 Shifting Harbors；名称未做商标检索。

**一句话：亲手把第一单货送进港口，马上收钱、换船、雇船长，再发现自己的航运正在改变下一单该去哪里。**

本方案把《网约车：接单人生》的轻松驾驶、连续接单与及时收益反馈，以及《网约车：从一辆破车干到一百辆》的订单判断、选路与车队成长，转译为地中海短程航运。前者提供驾驶感受参考，后者提供经营结构参考，不将两者混为同一种玩法。

## 本版确定的设计取向

- 主循环是接单 → 装货 → 亲自驾船 → 靠港交货 → 即时到账 → 升级或再接单。
- **普通短航从确认订单到到账，目标为20–30秒。** 这是熟悉操作后的体验假设，不是强制倒计时、保证实测结果或到时自动结算。玩家可以停下来欣赏海面，不因迟到扣款。
- 成长从一艘旧船到三艘小船队；亲自驾驶始终有价值。百艘规模是长期想象，不进入Game Off版。
- SHIFT的主机制是**货物流动改变港口供需，供需改变下一批订单价格和有利航路**。船长转向经营者是成长主题，风向变化是备选表现，两者都不能替代主机制验证。
- 首版使用四港、三货、五段航路、一个地图。提供明确的短篇结尾，不靠无限挂机填满体验。
- 目标平台为桌面浏览器，拟用俯视/斜俯视轻量表现。暂不锁定引擎，不从既有私有工程自动搬运代码或资产。

## 三个必须先回答的问题

1. 不加催单倒计时，20–30秒航行本身是否仍有操控和靠港乐趣？
2. 玩家是否能看懂“我刚送了这批货，所以这个港口不再那么缺货，下一条好路线变了”？
3. 第二艘船是否带来调度选择，而不是让玩家挂机或在菜单里多做一份工作？

前两项没有通过，先缩减或修改核心规则；不以更多港口、剧情、美术和船种掩盖问题。船队可缩成一艘助手船，但不能删掉从单船经营者成长的体验承诺。
