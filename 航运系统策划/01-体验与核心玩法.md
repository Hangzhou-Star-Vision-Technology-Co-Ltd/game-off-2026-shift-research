# 01 体验与核心玩法

## 1. 体验定位

玩家是地中海沿岸一位刚拥有旧货船的船长。远处是白墙港镇、暖色帆影和海岸线，眼前是一张能看懂的订单：运什么、去哪里、能赚多少、抵达后还有什么生意。亲自完成每次短航，财富和船队逐渐长大，海图上的商路也因自己的运输发生变化。

定位为**轻松驾驶＋短单经营＋小规模航运调度**。氛围要从航行中自然产生，经营要让玩家想再跑一单，不做真实船舶模拟、硬核贸易软件或海战养成拼盘。

目标体验假设：首次游玩12–18分钟能经历从旧船到小船队的一次完整成长，之后可继续自由航运。目标用户是愿意接受简单操控、喜欢接单赚钱和可见升级的轻度模拟经营玩家；该定位尚无市场验证，不据此推导留存或收入。

### 设计支柱

1. **钱是自己开船挣到的。** 货物从船上搬下，收入立即记入钱包，账单与船体反馈同时出现。
2. **每单有一个小判断。** 去哪里、走哪条路、亲自跑还是交助手，不在开船时弹大段选择题。
3. **成长能在海上看见。** 旧帆修好、货箱变多、第二艘船出港，胜过只增加面板数字。
4. **运输留下后果。** 港口从缺粮到稳定，相应报价降低；另一个港口和返程生意变得更值得关注。
5. **节奏快但不催促。** 快来自短航程、少菜单和快反馈，不来自惩罚性倒计时。

## 2. 核心循环和节奏

普通短航建议节奏如下，均为待测预算；决策用时不计入20–30秒目标：

| 阶段 | 玩家行为 | 目标反馈或预算 |
|---|---|---|
| 看单 | 看三张订单卡，比较终点、报价、航程和到港行情 | 没有8秒抢单限制；可自由思考 |
| 确认与装货 | 点击接单，货箱自动装船 | 约1–2秒，可跳过重复装货演出 |
| 离港与航行 | 控制方向和速度，看水路，避开礁石或绕行 | 约16–23秒有效驾驶 |
| 靠港交货 | 进入泊区并降低速度，确认自动交接提示 | 约2–4秒，不要求像素级对齐 |
| 结算 | 收入跳字、钱包变动、供需变化解释 | 入港交货后立即到账；演出不锁住继续操作 |
| 下一步 | 原地接单、查看海图、升级或派船 | 默认留在当前港口，不强制回母港 |

不会发生“时间到了就算完成”。只有实际到达正确港口、满足泊区条件并交付已接货物，订单才结束。远航若不能压进节奏，则单列为可选长航，不偷偷延长全部普通订单。

### 一分钟能看见什么

开场不先要求命名、注册、选择难度或读世界观。画面直接停在一艘旧船和一张安全订单旁。玩家点击接单，跟随清楚航标驶出港口，放慢靠岸，看到第一次到账和目的港缺货下降。第二张订单即出现新的港口选择。目标是“不到一分钟理解我在做什么”，不是一分钟内强制完成教程。

## 3. 视角与操控

### 默认输入

- A/D或左右方向键转向，W/上方向键加速，S/下方向键减速；减速到零后停船，不默认为倒车。
- 方向以船头为基准；进入游戏前用短箭头示意，避免用户把它误解成屏幕上下左右直接移动。
- Space或屏幕大按钮执行当前单一交互，例如接单、查看码头；不得同时绑定加速和接单。
- Esc暂停。Tab或屏幕海图按钮打开订单/船队面板并暂停世界；关闭后回到原航行状态。
- 第一版不以Shift键承担主题，也不强迫玩家同时操作船帆角度、风力、潮水和船员。
- 鼠标点击航点辅助转向是P1选项；若做，必须有等效键盘操作，不让辅助模式获得更高收入。

### 船的手感目标

保留轻微惯性、船尾水花和转弯半径，让它像小船而非鼠标光标。松开加速逐渐减速；低速时转向更容易，高速转弯更宽，但不能让新手在港口长时间打转。船体碰撞只造成短减速与轻微货损反馈，不沉船、不扣除本金、不强制维修后才能继续。

靠港采用宽容辅助：进入有明显边界的泊区，速度低于门槛，持续短时间即可交货。建议起始门槛为最高速的35%、停留0.5秒；属于原型假设。泊区内若无对应订单，只显示港口菜单，不误触结算。方向朝向码头可作视觉引导，不作为首版额外判定。

### 防卡住

撞到岸线后可以减速并缓慢转出。若仍卡住，提供“回到最近安全水面”按钮；需要确认以免误点，但不收费、不销毁货物、不改报价。重置位置后保持同一订单与货损状态，不能借此获得完好奖励或直接传送到目的港。最近安全点不得跨越未经过的航段。

## 4. 订单结构

港内展示最多三张当前可接订单，不使用滚动瀑布流。每张卡默认显示：

1. 起点 → 终点与货物图标；
2. 固定基础实收、可选完好交付奖励，避免只显示夸大的含奖励总额；
3. 预计短航时间和两种路线的差异；
4. 目的港缺货条与“本单将缓解什么”；
5. 到港后当前可见的潜在返程方向，标明仅为预览、未锁价；
6. 接单按钮，若不符合载量或来源库存条件，说明原因。

订单报价在接单时锁定，不因玩家慢慢开船或其他船先交货而缩水。未接订单可随供需刷新；刷新时保留卡片位置并显示变动，不在用户点击期间偷偷换单。每张单使用唯一标识，确认时再次检查是否可接。

MVP只允许旗舰同时持有一张订单，避免堆单路线优化掩盖驾驶体验。装货自动完成，无商品采购成本，不用先借钱买货；玩家经营的是运输服务，不是囤货炒价。取消未装货订单无损；装货后取消则货物在下一港按系统回运处理，取消无收入，货物归回来源账本，不能通过取消增加任一港库存。

### 订单类型范围

| 类型 | 首版处理 | 设计用途 |
|---|---|---|
| 普通货运 | P0，全部无迟到罚款 | 证明接单、驾驶、结算闭环 |
| 易损货运 | P1，清楚展示最多可损失的奖励 | 让稳妥靠港产生可选回报 |
| 港务信件 | P0保底单，固定低收益、不改变物资库存 | 避免没有可执行货单导致软锁 |
| 多港连单、乘客、救援 | 不进MVP | 需要额外界面、剧情或状态，不只是换图标 |

## 5. 地图与航路

首版以地中海为风格参考，使用**压缩比例、非真实航时**的四港海图：马赛、热那亚、巴勒莫、突尼斯。地理方位供识别和氛围，不声称还原历史贸易、真实海岸线或真实航海导航。

五段可航连接：马赛—热那亚、热那亚—巴勒莫、巴勒莫—突尼斯、突尼斯—马赛、热那亚—突尼斯。地图布局压缩成一屏可读的网络；边的长度按玩法调节，而不是按现实里程同比缩放。订单只生成在相邻港之间，避免20–30秒目标被跨地图距离破坏。

每个相邻港之间保留宽水路与局部近岸捷径。最短线可能更易碰礁，外海绕行宽松；两者都能抵达。首轮先让一组港口具有这类二选一，其余用简单路线，验证后再复制。不能做“图上两条路，实际永远同一条更快更安全”的假选择。

### 两层航路变化

- **P0经济航路变化：** 港口缺货和报价变化后，适合赚钱的下一条线路转移。海图用货物图标、粗细线和箭头表现，水路本身仍然畅通。这是主SHIFT机制。
- **P1物理航路变化：** 一次预告的局部顺逆风或施工绕行，改变操作难度和航行时间。只有基础循环通过才考虑；事件变化不得把已接订单变成不可完成。

不得只切换海面颜色却宣称航路策略变化，也不得把普通价格上下浮动当成已证实有趣。需要通过02章的因果样例和03章的对照测试证明选择真的变了。

## 6. 前十分钟成长节拍

以下为体验顺序，不是强制时钟脚本；玩家操作较慢时不催促、不惩罚。

| 阶段 | 新内容 | 保持不变的熟悉动作 |
|---|---|---|
| 开场至第二单 | 看见货物、泊区、即时到账 | 一张安全单，路线清楚 |
| 第三至五单 | 比较三张单；首次看到供需变化 | 驾船和交货操作不变 |
| 第一次升级 | 换新帆或改善舵机，立即体验差异 | 不打开长技能树 |
| 首次扩船 | 买第二艘船并指定一个港口订单 | 自己继续亲自跑单 |
| 后续数单 | 助手到港，提示该港已不缺这类货 | 调整路线，不需频繁点收钱 |
| 小船队成立 | 三艘船、四港服务记录和明确结尾 | 可继续自由航运，不强制重置 |

不要为了卡在某分钟出现而免费发船破坏经济；如果成长慢，调价格、收益或菜单负担。首轮成长数值在02章统一列出。

## 7. 成功、失败与结束

本作普通模式没有整体倒计时。失败是一次交付没有拿到完好奖励或跑了不划算的航路，不是“一次撞船就破产”。钱不为负，不设置强制贷款、生活费、拖欠工资、体力或每天登录奖励。

Game Off短篇结尾建议条件：拥有三艘船，四个港口各完成至少一单实物货运，并至少使两个不同“港口＋货物”的状态从缺货变为稳定。条件由明确任务条显示，可在正常接单中达成；信件不计入实物指标。若第三艘船使节奏明显拖长，可将结尾缩为两艘，但需在测试记录中说明取舍。

结尾显示实际航迹、最常运输的货物、服务过的港口和船队合影，解释“你把生意从这里带到了那里”。不把供需指数包装成历史经济评价。提供继续经营、重开、返回标题；新开档要确认，防止丢失已有进度。

## 8. UI与信息层级

### 航行HUD

- 上方：当前订单终点、已锁定实收、货物图标；没有红色催命秒表。
- 船旁：柔和目的地方向箭头，接近港口才出现泊区边界和减速提示。
- 角落：钱包、两艘助手船的简短状态、静音/暂停入口。
- 海图热度默认只显示与当前货物或选中订单有关的一层，避免三货十二条库存同时刷屏。

### 交货反馈

到账先完成，再播放短金币/账单动画。结算信息最多三行：“运费＋完好奖励－运营成本＝实收”“粮食库存20→30”“缺货减少，下批同类运费降低”。库存变化必须说明是实际交货还是后续生产消费，不把两种变化混成一个难以核对的数字。

### 港内界面

同一个面板承载接单、船队、升级三个页签，不能叠五层窗口。回退关闭最上层，不吞掉订单。新手阶段突出下一单，不在每次抵达时弹出商店。订单与派船界面都暂停世界，避免玩家读字时错过助手调度或被迫抢单。

### 辅助与可访问性

港口用名称、图标和形状区分，颜色只是补充。允许关闭镜头晃动和水面闪烁，字幕替代关键音效；音量分别调音乐与效果。按钮至少经过小窗口测试，保留清晰焦点和键盘确认路径。中文版与简短英文操作说明可作为参赛可访问性目标，不是官方语言硬性要求。

## 9. 美术、音乐与内容预算

建议统一为暖色地中海纸海图与清晰船形，海水纹理不妨碍识别礁石。近景码头、白墙红顶、帆面和装卸动画承担地域氛围，避免制作可步行城市。四港各一个轮廓地标和一种主色，三个货物图标、三档船体轮廓、少量水花和靠港反馈即可支撑首版。

声音优先完成海风、船身/水声、接单、到账、擦碰、助手归港六类可区分反馈。音乐可采用一段轻量循环和结尾变化，首次交互后再解锁浏览器音频，不自动突然爆音。音乐风格只作为原创方向，不模仿特定在世艺人，也不复制参考作曲目。

没有确定素材前，先用合法占位验证尺寸、可读性与性能。来源、作者、许可、是否允许仓库再分发、修改范围、AI辅助情况逐项记录。概念图不作为已完成游戏截图；本次策划不上传或复用第三方美术和音乐。
